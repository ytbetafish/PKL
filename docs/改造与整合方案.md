## 二、目标框架与工具链（本机实测）

- SDK：`.NET 10 SDK 10.0.403` 安装于 `C:\Users\adminstartor\.dotnet`（系统盘仅有 .NET 8 SDK，不足）。
- 构建时需设置环境变量（写入项目内可写目录，避免沙箱权限问题）：
  ```powershell
  $env:DOTNET_ROOT='C:\Users\adminstartor\.dotnet'
  $env:Path='C:\Users\adminstartor\.dotnet;'+$env:Path
  $env:DOTNET_CLI_HOME='<proj>\.dotnet-home'
  $env:DOTNET_CLI_TELEMETRY_OPTOUT='1'
  $env:DOTNET_SKIP_FIRST_TIME_EXPERIENCE='1'
  $env:NUGET_PACKAGES='<proj>\.nuget\packages'
  $env:NUGET_HTTP_CACHE_PATH='<proj>\.nuget\http-cache'
  ```
- 解决方案：`Plain Craft Launcher 2.slnx`（新式 XML slnx，.NET 10 支持）。
- PCL-CE 还原已验证通过（5 个项目全部 restore 成功）。

## 三、PCL-CE 工程结构

```
PCL-CE/
├─ PCL.Core/                 # 核心工具库（JSON、日志、网络、数学、扩展）— 保留，MC 无关
├─ PCL.Core.Wpf/             # WPF 适配层（主题、控件、动画、图标）— 保留
├─ PCL.Core.SourceGenerators/# 源生成器 — 保留
├─ PCL.Core.Test/            # 单测 — 保留
├─ PCL.Launcher.Core/        # 业务核心（实例、账号、下载、Mod 平台）— 大量 MC 代码，需剥离
│   └─ Minecraft/            # 【删】MC 实例/版本/账号体系
└─ Plain Craft Launcher 2/   # WPF 主程序（Pages/ 下大量 MC 页面）— 界面整体替换为 KSP
```

## 四、改造策略

### 4.1 剥离 Minecraft
- **保留（骨架底座）**：`PCL.Core`、`PCL.Core.Wpf`、`PCL.Core.SourceGenerators`；主程序的 `Application.xaml`/启动、主窗口外壳与导航、主题资源字典、设置持久化（JSON）、下载引擎（Downloader）、日志系统、自动更新框架。
- **删除（MC 专属）**：`PCL.Launcher.Core/Minecraft/*`、版本隔离与版本管理、MC 账号（微软/离线/皮肤）、Java 检测、Forge/Fabric/NeoForge 加载器安装、Mod 平台（Modrinth/CurseForge 针对 MC）、资源包/光影/存档/服务器等 MC 页面。
- 每删一处，修复其编译引用，保证 `dotnet build` 持续通过。
- 主程序更名 **PKL**，产品名改为 "PKL — KSP Launcher"。

### 4.2 集成 CKAN
- 将 `CKAN/Core` 源码纳入仓库 `external/CKAN.Core`，以**项目引用**方式加入解决方案（不强行合并 CKAN 的 GUI/命令行）。
- 新增 `src/Pkl.Ckan` 封装层，对外暴露：
  - KSP 实例自动探测（常见安装路径 + 手动选择）、`GameInstance` 加载；
  - 模组仓库/注册表刷新、模组列表与搜索、已安装/可更新列表；
  - 安装计划（依赖解析）与执行（下载+安装，进度回调）。
- 数据契约（供 UI 绑定）：`KspInstanceInfo`、`ModSearchResult`、`ModInstallPlan`。

### 4.3 简介翻译
- 复用 PCL-CE 已有的"简介翻译"实现：抽出为 `ITranslationService`，通过可配置的翻译/大模型 HTTP API 将模组描述译为中文。
- UI：模组详情区提供"原文 / 译文"切换，带缓存。

## 五、最终页面骨架（替换 MC 页面后）
1. **主页**：KSP 实例状态、启动按钮。
2. **模组管理**：浏览/搜索 CKAN 模组、安装/更新/卸载、依赖解析、简介翻译切换。
3. **设置**：KSP 路径、翻译 API、下载引擎、主题、关于。
